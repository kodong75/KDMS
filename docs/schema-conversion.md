# 스키마 변환 (2단계)

> 상태: 완료 · 최종 갱신: 2026-10-09 · a43a5f8 · 근거: PR #4(2단계 머지 2026-10-06), WORKLOG 2026-10-01 2단계

[plan.md](plan.md) §6 2단계: 원천 카탈로그 읽기 → 변환 규칙 적용 → 대상 DDL(Data Definition Language, 정의 언어) 생성·적용 → `kdms plan` 보고서.
규칙 파일 형식은 [plan.md](plan.md) §5, 기본값은 `src/main/resources/kdms-rules.yml`(주석에 키·허용 값), KDMS_MOCK 용 덮어쓰기는 `config/kdms-rules.yml`.

## 1. 명령

| 명령 | 하는 일 | 바꾸는 것 |
|---|---|---|
| `kdms plan` | 원천 카탈로그(`sys.tables/columns/indexes/foreign_keys/check_constraints/triggers/sequences/objects`)를 읽고 규칙을 적용해 보고서와 DDL 세 파일을 만든다 | 없음(원천은 읽기만, 대상은 접속 안 함) |
| `kdms plan --scan` | 위 + 원천 데이터를 테이블마다 한 번 훑어 NUL 문자(A02)·센티널 날짜(A08) 행 수를 센다 | 없음. 큰 DB 는 오래 걸린다 |
| `kdms schema` | `plan` 과 같은 계획을 만들어 **적재 전 단계 DDL** 을 대상 PG 에 한 트랜잭션으로 적용, 작업(`kdms.job`, 상태 `SCHEMA_DONE`)·테이블(`kdms.job_table`) 등록 | 대상 PG |
| `kdms schema --phase post-load` / `cutover` | 적재 뒤 UNIQUE·인덱스 / 전환 때 FK 만 적용(3·5단계가 부를 것. 손으로도 가능) | 대상 PG |

- 출력 폴더 기본값 `out/<작업 이름>/`(커밋하지 않음): `plan.txt`(보고서), `10_pre_load.sql`, `20_post_load.sql`, `30_cutover.sql`. psql 로 직접 실행해도 같은 결과다.
- 종료 코드: 0 통과/적용, 1 설정 오류, 2 접속·적용 실패, **3 계획에 오류**(규칙 파일을 고친다), 4 적용 거부(이미 있는 테이블, 적재가 시작된 작업).
- 대상에 같은 테이블·시퀀스가 있으면 멈춘다. `--replace` 를 붙이면 지우고 다시 만든다(안의 데이터도 지워진다). 작업 상태가 `LOADING` 이후면 `--replace` 도 거부한다.
- 실패하면 전부 되돌린다(PG 는 DDL 도 트랜잭션).

## 3. 규칙이 DDL 에 들어가는 곳

| 원천 | 대상 | 규칙 키 | 근거(KIS) |
|---|---|---|---|
| 자료형 | `types.<타입>.to`. `{n}` 문자 수(nvarchar 는 바이트/2), `{p}` 정밀도(시간형은 소수 자릿수), `{s}` 스케일. `(max)` 는 `max`. 별칭 타입(UDT)은 기반 타입 규칙 + 경고. 규칙 없는 타입(geography 등)은 **오류** | `types`, `tables.<t>.columns.<c>.type` | normalization §1, datatype-pitfalls |
| datetime2(7)·time(7)·datetimeoffset(7) | `timestamp(6)` 등. 값 규칙에 `round: half_up` 를 남겨 3단계 적재·검증이 같은 반올림을 쓴다 | `max_precision`, `round` | A06 |
| tinyint | `smallint CHECK (col BETWEEN 0 AND 255)` | `types.tinyint.check` | |
| 문자 컬럼 콜레이션 | 모든 문자 컬럼에 `COLLATE "C"`(DB 기본값에 기대지 않는다). `ci` 면 원천 CI 컬럼에 `kdms_ci` | `collation.target` | B01·B06·G08 |
| CI(대소문자 무시) UNIQUE | `CREATE UNIQUE INDEX … (lower(col))`. FK 가 그 키를 가리키면 일반 UNIQUE 제약도 둔다(FK 는 식 인덱스를 못 가리킨다). PK 에 CI 문자 컬럼이 있으면 PK 는 그대로 + `<pk>_ci` 유일 인덱스 | `collation.ci_unique: lower_index` | B14 |
| NULL 허용 컬럼의 UNIQUE | `NULLS NOT DISTINCT`(MS-SQL 처럼 NULL 1건만, PG 15+) | 자동 | |
| 필터 인덱스 | `[col] IS [NOT] NULL`·비교·상수만 있는 조건은 `WHERE` 로 옮긴다. 그 밖은 만들지 않고 경고 | 자동 | |
| IDENTITY | `GENERATED BY DEFAULT AS IDENTITY`(시작·증가값이 1,1 이 아니면 `START WITH … INCREMENT BY …`). 정수 타입이 아니면 **오류** | `identity.to` | A09 |
| SEQUENCE | `CREATE SEQUENCE … AS <타입> START WITH … INCREMENT BY … MINVALUE … MAXVALUE … [NO] CYCLE`. decimal 시퀀스는 bigint + 경고 | 자동 | B09·B13 |
| 기본값 | 상수(`((0))` → `0`, bit → `false/true`, `('Y')` → `'Y'`), `NEXT VALUE FOR` → `nextval(…)`, 인자 없는 함수는 표로(`getdate()` → `LOCALTIMESTAMP` 등). 그 밖의 식은 **오류**(컬럼별 `default` 로 직접) | `defaults.functions`, `tables.<t>.columns.<c>.default` | B13 |
| 계산 컬럼 | `generated` 에 PG 식이 있으면 `GENERATED ALWAYS AS (식) STORED`(적재·반영에서 뺀다). 없으면 **오류**. `value_with_warning` 이면 일반 컬럼 + 원문 COMMENT(KIS mock.sql 방식) | `computed_columns.action`, `tables.<t>.columns.<c>.generated` | B12, plan.md §4.4 |
| 이름 | 소문자(`identifiers.case: lower`, 원천 이름을 소문자로만 바꾼다). 63바이트 초과 테이블·컬럼 이름은 **오류**. 테이블마다 같은 인덱스 이름은 `이름_테이블` 로 바꾼다(PG 는 스키마 안에서 겹치면 안 됨) | `identifiers.*`, `tables.<t>.columns.<c>.name` | |
| 트리거·CHECK·뷰·SP·함수·SYNONYM | 옮기지 않고 경고·목록(KIS:docs/appcompat.md 로 수작업) | | B11, C01~C04 |
| PK 없는 테이블 | 만들기는 하고 경고(전환 때 전체 재적재) | | plan.md §4.6 |

값 규칙(끝 공백·대소문자·NUL·센티널·반올림)은 DDL 을 바꾸지 않는다. 계획(`SchemaPlan.ColumnPlan.value`)에 컬럼마다 남겨 3단계 적재기·4단계 반영기·검증이 같은 규칙을 쓴다.
`--scan` 에서 NUL 이 나온 컬럼은 `text.nul_char: fail`(기본)이면 **오류**로 멈춘다(T-L09).

## 4. KDMS_MOCK: KIS `sql/20_pg/gen/mock.sql` 과 비교 (2단계 완료 기준)

**컬럼 타입은 7개 테이블 55개 컬럼 모두 같다.** 노트북 실측 KDMS_MOCK 도 이 7개 테이블이다(KIS #23 의 `dbo.file_attach` 는 노트북 MIG_MOCK 에 없다. 나중에 생기면 `SourceCatalogIT` 가 차이로 알려 준다).
`SchemaPlannerTest.KDMS_MOCK_대상_타입은_KIS_mock_sql_과_같다`(mock.sql 값을 그대로 옮겨 비교)와
`TargetDdlIT`(PG 에 실제로 만든 뒤 `format_type` 으로 읽어 비교)가 확인한다. 시험 고정값(`KdmsMockCatalog`)이 실제 원천과 같은지는 `SourceCatalogIT` 가 Mac 에서 확인한다.

타입 밖의 차이는 모두 규칙 결정이다.

| 항목 | KIS mock.sql | KDMS (기본 + config/kdms-rules.yml) | 규칙 |
|---|---|---|---|
| 대상 스키마 | `mock` | `dbo` | `identifiers.schemas: { dbo: mock }` 이면 같아진다 |
| 문자 컬럼 콜레이션 | DB 기본(C.UTF-8) | 컬럼마다 `COLLATE "C"` | `collation.target: C` (비교 결과는 같다) |
| tinyint | `smallint` | `smallint CHECK (… BETWEEN 0 AND 255)` | `types.tinyint.check` |
| 기본값 | 없음(앱 호환 단계에서 따로) | `DEFAULT 0/false/'Y'/LOCALTIMESTAMP/gen_random_uuid()/session_user/nextval(…)` | `defaults` (B13) |
| 계산 컬럼 `rating_rank`, `file_ext` | 일반 컬럼 + 원문 COMMENT | `GENERATED ALWAYS AS (…) STORED` + 원문 COMMENT | `config/kdms-rules.yml` 의 `generated` (B12). `rating_rank` 는 원천 CI 비교에 맞춰 `upper(rtrim(…))` |
| `uq_app_user_login`, `uq_issuer_cd` | `UNIQUE (col)` | `CREATE UNIQUE INDEX … (lower(col))` | `ci_unique: lower_index` (B14) |
| `pk_code_master`, `pk_daily_count` | PK 만 | PK + `pk_…_ci` 유일 인덱스(lower) | 같은 규칙. CI 키라서 |
| FK | 적재 뒤 바로 | 전환 때(`30_cutover.sql`) | plan.md §3.1 |
| setval | 생성 시점 값으로 바로 | 전환 시점 원천 값으로(5단계) | A09 |
| 시퀀스 | `START 202600001` | `START WITH 202600001 … MINVALUE -9223372036854775808 MAXVALUE 9223372036854775807 NO CYCLE` | 원천 값 그대로 |

예상 경고 9건(트리거 `trg_rating_audit`, uniqueidentifier·rowversion 타입, `getdate()`·`sysdatetime()`·`newsequentialid()`·`suser_sname()` 기본값, 자동 변환 안 하는 객체 6개)과
주의 3건(CI 비교 B01·B03·B06, 끝 공백 B02·B04, CP949 바이트 B05·A03).
`--scan` 을 붙이면 KIS 가 심은 NUL(`dbo.issuer.issuer_nm`) 때문에 오류 1건으로 막힌다. 3단계에서 `config/kdms-rules.yml` 에 이 컬럼만 `nul_char: replace`(U+FFFD) 로 정했다(2026-10-06, [load-verify.md](load-verify.md) §4). 기본 규칙 그대로면 여전히 막힌다.

## 5. 원천 권한

카탈로그 뷰만 읽는다: DB 사용자 + `VIEW DEFINITION`(계산 컬럼 식·기본값 원문). `test/sql/mssql/20_grant_kdms_login.sql` 이 이미 준다.
